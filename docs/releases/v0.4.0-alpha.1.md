# IndexCore v0.4.0-alpha.1

## Release contract

This release freezes the accepted P0-P12 Alpha implementation behind a
reproducible tag-driven release pipeline. The release-engineering commit adds
no production behavior or contract changes.

- Release: `v0.4.0-alpha.1`
- Release commit: the commit referenced by tag `v0.4.0-alpha.1`
- Validated functional baseline:
  `d7c49e8a2cc1c51ac1eb199547e8d3f172ce6332`
- `FROZEN_CONTRACT_CHANGES: NONE`

The exact release commit and immutable image digest are recorded in the GitHub
Pre-release generated by `.github/workflows/release.yml`.

## Published artifacts

The workflow publishes these GHCR tags for `linux/amd64` only:

- `ghcr.io/nathanxiangang-web/index-core:v0.4.0-alpha.1`
- `ghcr.io/nathanxiangang-web/index-core:sha-<release-commit-short-sha>`
- `ghcr.io/nathanxiangang-web/index-core:alpha`

The version and SHA tags identify the release commit. The `alpha` tag is the
only moving tag. This release does not publish `latest`, `stable`, or
`v0.4.0`.

The workflow injects the following build metadata into the binary and verifies
the output from the image by immutable digest before creating the Pre-release:

- `VERSION=v0.4.0-alpha.1`
- `COMMIT=<release-commit-sha>`
- `DATE=<UTC-build-time>`

## Validation boundary

- P12: **SHORTENED CROSS-REPO TEST VALIDATION -- ARCHITECT_ACCEPTED**
- Long acceptance soak: **NOT RUN / NOT CLAIMED**
- The incremental/hybrid runtime remains default disabled.
- Runtime default-on is **NOT AUTHORIZED**.

The tag workflow repeats the repository's stable validation boundary before
publishing: formatting, `go vet`, `go build`, the full PostgreSQL 18 test suite,
and the targeted race suite for the hybrid runtime and application lifecycle.
